# Décisions (ADR courtes)

| # | Décision | Pourquoi |
|---|---|---|
| 1 | **Electron** (pas Tauri) | Même Chromium sur Win/Linux/Mac ; Tauri = WebKitGTK sous Linux (tray/rendu inégaux). Le < 300 ms est obtenu en gardant la fenêtre kanban pré-chargée et cachée. |
| 2 | Moteur = **sidecar Python** (FastAPI, uv) | Écosystème audio/STT (faster-whisper, soundcard). Lancé par Electron, handshake JSON sur stdout, s'arrête quand stdin se ferme. |
| 3 | **Le token ne quitte jamais le process main** | Le renderer passe par IPC (`hark:api`) → main ajoute le Bearer. Pas de CORS, pas de token dans le DOM. |
| 4 | API **loopback only** + contrôle `Host` + refus des requêtes avec `Origin` | Protège contre le DNS rebinding et les pages web qui tenteraient d'appeler l'API locale. |
| 5 | Token maître dans le **gestionnaire d'identifiants de l'OS** (`keyring`) | Repli : fichier `0600` si aucun backend (Linux headless), avec avertissement. |
| 6 | **Pydantic = source de vérité** des contrats → `/contracts/*.schema.json` → types TS générés | Un test casse si l'un des trois dérive. |
| 7 | Les tâches venant de l'IA / plugins / MCP **ne peuvent pas choisir leur colonne** | `TaskProposal` n'a pas de champ `column` (et `extra=forbid`) : elles arrivent toujours dans « À valider ». |
| 8 | Détection de réunion : son ≥ seuil N s **+ micro utilisé par une autre app** (configurable) → notification avec **[Enregistrer] [Non]**, qui disparaît après quelques secondes (= ignorer). On n'enregistre **que** sur clic. | Réponse Q1. Le signal micro est ce qui sépare un appel d'une vidéo YouTube. |
| 8b | Précision sur la détection : le **signal d'appel est « une autre application utilise le micro »** (Linux : `pactl list source-outputs`, flux lisant une source `.monitor` exclus ; Windows : registre `CapabilityAccessManager`). Un simple processus Teams/Zoom ouvert **ne suffit pas** (il tourne toute la journée) : le nom de l'application sert seulement à étiqueter la notification. `require_mic_in_use=false` donne un mode « audio seul », moins précis. | Évite les faux positifs YouTube tout en couvrant les appels, sans IA. |
| 9 | macOS (capture du son système) **reporté** à une version ultérieure. L'abstraction de capture le prévoit. | Réponse Q2. |
| 10 | Voix → personnes, inspiré de voicebox (`VoiceProfile` + `ProfileSample`) : `Person` + échantillons/embeddings, reconnaissance proposée, validée par l'utilisateur. Étape 4b. | Réponse Q3. |
| 11 | **Profils de modèles** (Léger / Équilibré / Précis) pour Whisper et Ollama, avec gestionnaire de téléchargement explicite. | Réponse Q4 (inspiré du gestionnaire de modèles de voicebox). |
| 12 | Fin de réunion : après X min de silence, notification « Réunion terminée ? » qui **reste affichée** jusqu'à ce qu'une voix revienne (elle se ferme, l'enregistrement continue) ou que l'utilisateur arrête. Pas d'arrêt automatique. | Réponse Q5. |
| 16 | Enregistrement en **WAV** 16 kHz mono PCM16 (pas FLAC), un flush par bloc de 0,25 s. | libsndfile ne relit pas un FLAC dont l'en-tête n'a pas été finalisé (crash) ; un WAV se récupère à partir de la taille du fichier. Taille ≈ 115 Mo/h/piste, acceptable car l'audio est supprimé après transcription par défaut (compression FLAC possible plus tard si rétention). |
| 17 | Le démarrage manuel (`POST /v1/recording/start`) est réservé au scope `ui` ; plugins/MCP ne peuvent **jamais** lancer un enregistrement. | Consentement : seul un clic de l'utilisateur dans l'app démarre l'audio. |
| 18 | Événement ajouté `meeting.silence` (`silent: true/false`) en plus de la liste d'origine. | Nécessaire pour afficher/retirer « Réunion terminée ? ». |
| 19 | **Garde réseau** (`net/guard.py`) installée au démarrage du moteur : toute connexion ou résolution DNS hors loopback lève `NetworkBlockedError` et est comptée (`blocked_attempts()`). Seul `allow_network()` (téléchargement de modèle demandé par l'utilisateur) la lève. | Rend vérifiable le critère « aucun appel réseau sortant ». Un test de bout en bout vérifie 0 tentative. |
| 20 | **Profils de modèles** Léger / Équilibré / Précis / Très précis (base / small / medium / large-v3-turbo), recommandation selon RAM et GPU, téléchargement **explicite**. La transcription charge les fichiers avec `local_files_only=True` ; `HF_HUB_OFFLINE=1` en permanence. | Réponse Q4 ; aucune connexion implicite. |
| 21 | Rétention : audio supprimé dès la transcription réussie (défaut), ou 7/30 jours (purge horaire). Un échec ne supprime jamais l'audio. | Contrainte de confidentialité du brief. |
| 22 | Recherche FTS5 unique (`search`) alimentée par le dépôt (titres, segments ; résumés à l'étape 5), tokenizer `unicode61 remove_diacritics 2`, requête utilisateur assainie (termes entre guillemets, préfixe sur le dernier). | Accents français, pas d'injection d'opérateurs FTS. |
| 23 | **LLMProvider** : `OllamaProvider` (local, par défaut, URL obligatoirement loopback) et `CloudProvider` (OpenAI-compatible) **désactivé** : il faut cocher l'accusé « le texte quitte ma machine », fournir une clé (keyring) et le choisir ; le réseau n'est ouvert (`allow_network`) que pendant l'appel. | Contrainte de confidentialité ; le cloud n'est jamais un défaut ni un repli silencieux. |
| 24 | **Pipeline** : blocs ≤ `chunk_tokens` → résumé par bloc (sauté si un seul bloc) → une passe finale JSON ; estimation pessimiste **avant** appel (refus si > budget), comptage réel pendant ; un seul essai de réparation du JSON. Schéma envoyé au serveur plat (sans `$defs`) puis re-validation Pydantic. | Maîtrise des tokens ; compatibilité des sorties structurées. |
| 25 | **Cache par hash** `sha256(version des prompts, fournisseur, modèle, taille des blocs, profil, transcription)` ; le déclenchement automatique ne ré-analyse jamais une réunion déjà analysée ; seul un clic (« Ré-analyser ») force. Une ré-analyse ne duplique pas les tâches déjà au kanban. | « Jamais de retraitement d'une réunion déjà analysée ». |
| 26 | « Me concernant » est **déterministe** (pas laissé au LLM) : assigné = nom/surnom du `profile.yaml` ou « moi/je », ou, sans assigné, une phrase d'engagement dite sur **la piste micro** juste après la demande. Un assigné nommé qui n'est pas toi n'est jamais « à moi ». | Explicable et testable. |
| 27 | **Verrouillage réseau d'Électron** (`network.ts`) + **audit noyau** `scripts/audit-network.sh` (strace sur l'app réelle, échoue à toute connexion non loopback / proxy / DNS). Découvert par mesure : Chromium contactait `redirector.gvt1.com` à chaque lancement. | La garde Python ne couvre pas le process Electron ; « full local » doit se mesurer, pas se supposer. |
| 28 | **Annuaire d'équipe** (`people`) + `tasks.assignee_id` (ON DELETE SET NULL) en plus du texte libre `assignee`, que le moteur tient à jour avec le nom complet. Supprimer une personne garde son nom sur ses tâches. | Suivi d'équipe du lead sans casser les exports, plugins et tâches IA à nom libre. |
| 29 | Rattachement automatique IA → personne **seulement si non ambigu** (e-mail, nom complet, prénom ou nom unique) ; les intégrations ne peuvent que **relier** par e-mail, jamais créer une personne. | L'IA propose, l'humain dispose ; pas de doublons ni d'erreurs silencieuses. |
| 30 | **Panneau latéral droit** (fenêtre sans cadre, transparente autour d'une surface arrondie, toute la hauteur de l'écran de la souris, toujours au premier plan) et **colonnes empilées repliables** (état mémorisé, en-tête toujours zone de dépôt). Réunions en liste → détail. Style repris d'aska (jetons de couleur, typographie, `kbd`). | Demande utilisateur ; un panneau étroit impose l'empilement et la navigation liste/détail. |
| 31 | **Masquage au clic extérieur** (comme aska) : sur perte de focus, le panneau se masque sauf s'il est épinglé (réglage `hideOnBlur`, bouton 📌), si une boîte de dialogue de Hark est ouverte (`withDialog` : export, confirmations natives), si les devtools sont ouverts, dans les 300 ms après l'ouverture, ou si **le pointeur est dans le panneau** (liste déroulante / calendrier qui prennent le focus sur certains bureaux). Les `window.confirm` sont remplacés par une confirmation native via `hark:confirm`. | Un `confirm()` ou une liste déroulante ne doit jamais faire disparaître le panneau sous les doigts. |
| 14 | La notification de consentement est une **petite fenêtre Electron** (toujours au premier plan, affichée **sans prendre le focus**, identique sur les 3 OS), pas une notification native. Elle ne peut répondre qu'avec `record` / `decline` / `ignore` via IPC validé (l'expéditeur doit être cette fenêtre). | Les boutons d'action natifs sont peu fiables sous Linux ; ne pas voler le focus évite de perturber la réunion. |
| 15 | Flux d'événements **SSE** `/v1/events/stream` (scope `read`) dès l'étape 2 : le process main s'y abonne (toast + rafraîchissement du kanban en temps réel). Les plugins l'utiliseront à l'étape 6. | Un seul mécanisme d'événements pour l'app et les intégrations. |
| 13 | MCP : servi par le moteur (HTTP streamable `/mcp`) **+ shim stdio** qui relaie vers lui (modèle voicebox `mcp_shim`). | Une seule implémentation, un seul point de contrôle des permissions. |
